# 区域天花板:两个杠杆(2026-06-25，已实现+离线验证)

> 抬高第 1 步(圈区域)的召回天花板,从今天的 ~0.80 → **~1.0**。两个杠杆,都门控、默认关闭、离线已验证。

## 关键发现:我们的"金标"有 21% 根本不是代码行
在 AWQ substrate(1227 个金标行)上拆类型:
| 类型 | 占比 |
|---|---|
| 函数内代码 | 69.6% |
| 模块级代码(import/类体/装饰器) | 9.4% |
| **空行**(插入锚点) | **15.7%** |
| **注释/docstring** | **5.1%** |
| 越界 | 0.2% |

`parse_patch` 给"插入"打锚点 `(old-1, old)`,经常落在**空行**上。而 **ARISE 的金标定义明确排除空行**——所以我们一直在用一个**比 ARISE 更脏、更苛刻**的金标跟它比,自己吃亏。

## 两个杠杆(离线已验证,数字精确落点)
| 配置 | 区域召回天花板 |
|---|---|
| 现状(全部金标 + 现有区域) | **0.801** |
| **+ Lever 1**(金标对齐 ARISE,扔空行/注释) | **0.896** |
| **+ Lever 1&2**(对齐金标 + 整文件区域) | **1.000** |

- **Lever 1 = 改口径,免费 + 更公平。** 不是作弊,是改回和 ARISE 一样的金标。**附带**:我们之前报的 27.7/43.0/47.3 是在脏金标上算的,对齐后这些数大概率会上升 —— 之前对 ARISE 的差距被高估了。
- **Lever 2 = 真方法改进。** 一旦只看代码金标,缩区域确实在丢召回(0.896 vs 整文件 1.0,丢 ~10 分)。file-given 下,能塞进上下文的文件(70% ≤1500 行)直接用整文件当区域。

## 代码(门控，默认关闭)
- `p0_line_recall.clean_gold(gold, flines)` — 扔空行/注释/越界。
- `egl_e2e --arise-gold` — Lever 1(对所有臂统一应用,带/不带都报)。
- `egl_e2e --small-file 1800 --max-region 2000 --all-module-lines` — Lever 2(整文件区域 + 不截断 + 全模块行)。
- `region_loc._make_region`/`select_regions` 加 `max_region_lines`/`all_module` cfg。
- `ablation_rank_sweep --arise-gold` — 离线门控也支持对齐金标。

## 开机后建议跑(复用冻结文件定位)
```bash
# 基线(无杠杆,脏金标) 已是 egl_e2e_ARISE_static/dynamic.json
# 杠杆版:
<ENV> python egl_e2e.py --broad --sample 300 --workers 20 --file-loc arise \
  --reuse-files egl_e2e_ARISE_static.json --final-pick 8 \
  --arise-gold --small-file 1800 --max-region 2000 --all-module-lines \
  --out egl_e2e_levers.json
# 对比 line R@{1,5,10}:无杠杆 vs 有杠杆;并把历史 bf16 结果用 --arise-gold 重算一遍看"公平差距"
```

## 诚实提醒
这两个抬的是**天花板**(候选集里有没有金标的上限)。**realized R@k 还要靠下游的投票/裁判**——天花板从 0.80→1.0 是**必要不充分**。但它解除了"第 1 步卡死后面"的硬约束,B(建池)+A(裁判)才有发挥空间。大区域会让投票 prompt 变大(成本),这正是后面换成"逐块裁判"的动机。
