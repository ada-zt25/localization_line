## 0. TL;DR（一眼结论）

- **最优结果**：**DeepSeek-V3 = 36.1 / 64.6 / 71.9**（行 R@1/5/10，SWE-bench-Lite 端到端）。**@5(64.6) 反超 ARISE 的 62**；R@1/R@10 接近（41 / 74）。

- **两堵墙**：**R@1 = 排序问题**（金标在候选池约 85%，却排到 #1 只约 38%）；**R@10 = 文件墙**（line R@10 ≤ file R@10，ARISE 的 74 压在文件墙之上）。

## 1. 方法（精简后的核心流水线 = `region_loc.py` / `egl_e2e.py`）

```
Issue + 仓库 + 失败测试
  → ① 文件定位（agentic LLM）→ 候选文件
  → ② 区域收窄（核心创新）：Agentless 骨架元素选择（只给签名+行号 ~10% 体量）挑可疑函数/类
       + 图/覆盖兜底；把「2000 行里找行」变「~200 行里找行」。小文件(≤500行)跳过收窄。
  → ③ 区域内自洽投票：只对选中区域做带行号的行定位，k=5 次采样，按互逆排名(RRF)并集。
  → ④ RRF 排序：投票票数 + def-use 图分（+ 可选 coverage 优先）融合。
  →（⑤ final-pick：LLM 从 top-N 挑 #1。Qwen 阶段新增，+5.6 R@1；DeepSeek-V3 最优那版未用。）
  → 排序候选行 → 评测 R@1 / R@5 / R@10
```

## 3. 哪些杠杆有效 / 哪些无效（已确立，三组证据一致：n=20 gate · n=163 E4 · n=300 历史）

- ✅ **有效 = 区域收窄 + 自洽投票（+def-use 图）**：n=163 干净 E4 子集，`ours_static − arise_static(裸静态切片) = +12.9 / +20.9 / +19.6`，三个 k 的 CI 全排除 0；n=300 历史同样 +15~20pp 全显著。**投票是整个方法的发动机。**
- ✅ **final-pick（聚焦精排）**：Qwen AWQ 上 R@1 +5.6（23.4→29.0）。R@1 唯一有方向性增益的 LLM 杠杆。
- ❌ **无效，已删（`git stash` 可恢复）**：judge(裁判/CBA A-段)、blend、multi-view、Lever-2(整文件区域)、test-evidence、anchors。实测增益全在 n=20/163 噪声内（对抗验证 `wf_a93b1de5` 6-agent 读实测数据校准；所有 judge-vs-投票 配对 CI 都含 0）。

## 4. 为什么打不过 ARISE（两堵墙 + 同模型方法差距，均有数据）

1. **R@1 是『排序』问题**：金标在候选集里约 85%，但被排到 #1 只约 38%。同模型下排序器挑不出对的行。聚焦精排(final-pick)能补一点(+3~6)。
2. **R@10 撞『文件墙』**：硬约束 line R@10 ≤ file R@10。ARISE 的 74 压在文件墙之上；光做行定位最多约 67，够 74 必须**同时**抬文件召回。
3. **同模型方法更弱 + 弱验证器命门**：同模型(Qwen-32B)我们的方法本身弱于 ARISE，只有换更强的 DeepSeek-V3 才赢回 @5；LLM 当裁判精排零增益（弱验证器：同模型既生成又验证，挑不出对的行）。

## 5. 平台 / 工程教训

- 模型经 SSH 隧道连 AutoDL vLLM（Qwen-32B bf16，`--max-model-len 16384 --gpu-memory-utilization 0.90`，必须 screen）。
- **隧道极不稳**：网关踢长连接 + 频繁重连会触发限流。稳态打法 = 网页终端用 base64 单行起 vLLM（screen）+ **一条** `ssh -CN -o ServerAliveInterval=20 -L8000:...` 心跳隧道挂着不动 + 实验只走 localhost:8000、零额外 SSH。
- E4 n=300 因隧道渐进式掉线（投票空率前半 4% → 后半 97%），后半数据被毁，抢救出干净 n=163。**长实验前必须先解决连接稳定性，否则白烧 GPU。**
- vLLM 受显存约束 ~6 路并发（32B bf16 + 16K KV），workers 已喂饱，加 worker 无用。

## 附录 A：被推翻的早期判断（**别再当结论用**）

对抗验证（`wf_a93b1de5`）读实测数据后，下列 n=20 阶段的措辞被打回：

- **「Lever-2 因 16K 投票 prompt 溢出而坏」= 机制被证伪。** 失败实例池在**缩小**（sphinx-7738 77→37）、region_recall 塌成 0 = 金标**掉出池**，不是 prompt 溢出（溢出该让池变大/变空）。且只 2/20 题翻转，CI 含 0 = 噪声内。
- **「裁判=@1 精度工具」「multi-view 与裁判对抗」= 方向性但 n=20 噪声内**，所有配对 CI 含 0、符号跨 run 翻转（+15→+10→−5），不可作结论。
- **「arise_static 是 ARISE 复现」= 错。** 它只是 `g.line_scores_v2(use_coverage=False)` 纯静态 def-use 切片（内部弱基线，无投票/无 agent loop）；8.7 vs 论文 41 的差距是「裸组件 vs 完整系统」，预期内、非方法学差异。
