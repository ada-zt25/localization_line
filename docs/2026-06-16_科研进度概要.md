# 2026-06-16 科研进度概要：B5 方法、benchmark 表现与 B3/B4 对比

> 本文记录 2026-06-16 一整轮围绕 **B5 方法**的设计、实验与诚实结论。重点：B5 闭环方法、在 benchmark 上的表现、与 B3/B4 的对比、以及一连串改变方向的关键发现。
> 配套代码：`exec_oracle/pair_extractor.py`(Φ 抽取)、`witness_probe.py`(执行式认证)、`llm_extract.py`(LLM 抽取)、`rq2_vetted.py`(注入差分/regime/diagnose)、`fair_loop.py`(无泄漏公平闭环)。

---

## 0. TL;DR（最重要的几条）

1. **B5 的强,来自闭环的执行反馈,不来自静态抽取质量。** 静态注入(Φ 或 LLM 抽取规则)在下游≈B1;真正把分数拉起来的是"生成→执行→归因→精修"的闭环。
2. **原版 `B5_loop`(文档 §8,≈B4−0.09)有训练/测试泄漏**:闭环反馈用的 oracle = 评测打分用的 oracle。堵上泄漏(dev/held 拆分)后,B5 相对 B1 的优势大幅缩水。
3. **公平(无泄漏)条件下:B5_loop 明显 ≫ B0–B3(+0.25),但不超过 B4(gold)。** 没有任何纯 B5 方法稳定超过 B4。
4. **真正的瓶颈是"规则正确性",不是精度也不是召回。** 闭环只能放大一条正确规则:`loop+gold=0.875` 赢一切,`loop+噪声LLM规则=B1`。test-free 抽取产不出足够正确的规则。
5. **Φ 抽取召回从 0.48 提到 0.64**(return-flow 0/5→3/5,shared-receiver 1/5→2/5,精度守住),但 **shared-receiver 在 3 个库的文档里压根没写 → 静态抽取的硬天花板**。

## 1. B5 方法设计

### 1.1 条件定义（自变量梯度）

| 条件 | 注入内容 |
|---|---|
| B0 | 仅任务文字 |
| B1 | API 清单 |
| B2 | 原始文档片段 |
| B3 / B3\* | 理想/抽象调用序列(无成对约束) |
| B4 | API 清单 ⊕ 该任务的 **gold 成对规则**(人工抽取) |
| **B5_loop** | API 清单 ⊕ **Φ 抽取规则**,再经**闭环迭代** |

### 1.2 B5_loop 闭环（核心方法）

```
r_0 = Φ(lib, task)                       # 静态抽取初始规则
for t in 0..K-1:
    g_t = LLM(prompt(API_LIST, r_t, notes_t))   # 生成
    v_t = Oracle(g_t)                            # 执行判分
    if v_t.pass: stop
    a_t = Attribute(v_t)                 # 失败 → κ 逆映射到耦合通道
    r_{t+1}, notes = Refine(r_t, a_t)    # typed 规则精修 / 或 prompt 反馈
```
- **创新点(test-free 放弃后的定位)**:**typed 成对约束引导的迭代精修**——失败被映射到具体**耦合通道**(κ 双射的逆),精修的是一条**可迁移的 typed 规则**,而非只补一份代码。这是区别于普通 self-debugging/Reflexion 的地方。
- 代码:`b5_feedback.py::run_loop` / `attribute` / `refine_rule`。

### 1.3 本轮探索过的 B5 变体（及结论）

| 变体 | 说明 | 下游结论 |
|---|---|---|
| 静态 Φ-B5 | 一次注入 Φ 规则,无闭环 | ≈B1,没用 |
| 静态 LLM-B5 | 一次注入 LLM 读文档提的规则 | =B1,没用 |
| vetted-B5 | 探针过滤幻觉后注入 | 与 unvetted 无差(高先验库甚至 <B1) |
| **公平 B5_loop(Φ)** | Φ 种子 + 闭环,**dev/held 拆分** | **≫B0–B3,<B4** ← 主线 |
| 公平 B5_llm | LLM 种子 + 闭环 | 稳定后 =B1 |
| B4_loop(对照) | gold 种子 + 闭环 | 微超 B4(+0.042,噪声内) |

### 1.4 公平协议（去泄漏，关键）

原版 `B5_loop` 的闭环反馈 `benchlib.evaluate_source` 与最终评测是**同一个 oracle**,等于在测试集上优化("对着答案重试到通过")。修正(`fair_loop.py`):
- 每任务 INPUTS 拆成 **dev(反馈用)/ held-out(只评测)**;生成阶段绝不碰 held-out;
- **所有方法同样预算 K**:B0–B4 重采样选 dev 通过的(best-of-K),B5_loop 额外做 typed 精修;
- 评测在 held-out 上。
- 局限:63 任务中仅 31 个有 ≥2 输入可拆;主实验落在 **simplug(10)+glom(6)=16 个可拆任务**。

## 2. Φ 抽取质量（RQ1）

### 2.1 召回改进（本轮）

根因:`detect_DFR`/`detect_SS` 只解析**代码链/方法源码**,但 return-flow 与 shared-receiver 的信号写在**文档散文**里("navigates to nums"、"inverse maps value→key"、"same object/in place")。加了**文档文本线索检测器**(通用词汇、按线索去重)。

| | 精度 | 召回 | F1 |
|---|--:|--:|--:|
| 改进前 | 0.385 | 0.48 | 0.43 |
| **改进后** | 0.38 | **0.64** | **0.48** |

- return-flow 0/5→3/5,shared-receiver 1/5→2/5,**精度守住**。
- 试过的 access/param 额外线索因与判别打分相互干扰(把 glom 从 1.00 打回 0.75)被**回退**——典型 metric-fitting,避免。

### 2.2 Φ 能起作用的范围（6 库 × 6 类矩阵）

✅=恢复 gold;no=有该类但 Φ 漏;—=该库不含该类。

| 库 | param | return-flow | shared-recv | config-ret | lifecycle | completion |
|---|:--:|:--:|:--:|:--:|:--:|:--:|
| glom | ✅ | ✅ | no | ✅ | — | — |
| diot | ✅ | ✅ | no | ✅ | ✅ | — |
| simpleconf | no | no | no | ✅ | ✅ | — |
| bidict | ✅ | ✅ | ✅ | no | no | — |
| simplug | no | no | no | ✅ | ✅ | — |
| sqlitedict | — | — | — | — | — | ✅ |

**按类**:config-return 4/5、param 3/5、return-flow 3/5、lifecycle 3/4、**shared-receiver 1/5**、completion 1/1。总计 **16/25 = 召回 0.64**。

**规律**:**约束是"文档显式命名的 API/kwarg/上下文"→ Φ 抓得到;约束是"靠行为才看得出的"(同对象读写、合并优先级、名字vs对象)→ Φ 抓不到。**

### 2.3 诚实天花板

- **shared-receiver 在 diot/simpleconf/simplug 的文档里完全没写**("same/in-place/reflected" 词汇不存在)→ **基于文档的静态抽取器原理上抓不到**。
- simpleconf/simplug 只命中 config+lifecycle(各 2/5),而它们下游高价值的 param/return-flow 恰恰被漏——**"召回 0.40"高估了 Φ 的实际有用程度**。

### 2.4 探针（执行式认证，精度方向）

`witness_probe.py`:合成"遵守/违反"程序在真实库上跑,只留可观察分叉的规则。已去掉全部库特定常量(防"和写 gold 一样"的循环性攻击)。
- RQ1 精度:4 个库合计 **0.36→0.59(保守,零召回损失)**,16 条幻觉被实跑证伪。
- **但下游无效**:删幻觉对通过率无影响(幻觉良性;真害来自"正确规则用错任务",精度过滤管不着)。→ 探针是**精度**工具,而瓶颈在**召回/正确性**。

## 3. Benchmark 表现 与 B3/B4 对比（RQ2）

### 3.1 公平闭环主结果（simplug+glom,K=3,qwen2.5-coder:7b,无泄漏）

**单轮(含 B0/B3)**:
| 方法 | 通过率 |
|---|--:|
| B0 | 0.250 |
| B1 | 0.438 |
| **B3** | **0.438** |
| **B4(gold)** | **0.875** |
| **B5_loop(Φ)** | **0.688** |

→ **B5_loop − B3 = +0.25**,**B5_loop − B1 = +0.25**,**B5_loop − B4 = −0.19**。

**3 轮稳定(含 LLM 种子与 gold+loop 对照)**:
| 方法 | 通过率 |
|---|--:|
| B1 | 0.458 |
| B4(gold) | 0.833 |
| B5_llm(LLM 种子+闭环) | 0.458（=B1） |
| B4_loop(gold 种子+闭环) | 0.875（+0.042 over B4） |

### 3.2 与 B3、B4 的总对比（所有 B5 变体）

| B5 方法 | 设置 | vs B3 | vs B4 |
|---|---|:--:|:--:|
| 静态 Φ-B5 | 一次性,低先验库 | 未测 | 明显低(−0.25) |
| 静态 LLM-B5 | 一次性,低先验库 | 未测 | 明显低(−0.25) |
| **公平 B5_loop(Φ)** | 公平闭环 | **+0.25 ✅** | −0.19 |
| 公平 B5_llm | 公平闭环 | ≈持平 | −0.375 |
| 原版 B5_loop（**泄漏**） | 文档§8,6库5模型 | +0.27 | −0.09 |

**结论**:
- **比 B3:** 只有**带闭环**的 B5 明显赢(公平 +0.25);所有静态 B5 ≈ B1,赢不了 B3。
- **比 B4:** **没有一个纯 B5 方法稳定超过 B4。** 泄漏版最接近(−0.09 但有水分);公平版 −0.19;唯一微超 B4 的 B4_loop 用了 gold。

### 3.3 Regime 依赖（rule 何时有用）

- **高先验库**(bidict/diot/glom 对 qwen-coder,B1≈0.83):规则塞了也没空间,B5≈B1,甚至 unvetted-B5<B1。
- **低先验库**(simpleconf+simplug,B1≈0.46):**gold 明显有用(B4−B1=+0.18~+0.25)**,但静态抽取只拿到 +0.04 → **下游缺口是召回**(5/6 缺口任务为"Φ 抽取为空")。

## 4. 关键发现（诚实记录，按重要性）

1. **召回是瓶颈,不是精度。** 探针(精度)删幻觉对下游零影响;真正缺的是 Φ 漏掉的真规则(return-flow/shared-receiver/param)。
2. **闭环只放大一条正确规则。** `loop+gold=0.875` 赢一切;`loop+噪声LLM规则=B1`(B5_llm 恰好=B1)。→ **规则正确性是真瓶颈**,test-free 抽取产不出足够正确的规则,闭环也修不好错规则。
3. **训练/测试泄漏。** 原版 B5_loop 的"接近 B4"是泄漏刷出来的;公平后优势缩水。**任何"B5>B4"的主张必须用 dev/held 拆分 + 同预算基线,否则会被顶会判"在评测集上调参"。**
4. **test-free 与"强"不可兼得(当前机制下)。** 强 = 闭环执行反馈(用测试,不 test-free);test-free 静态 = ≈B1。test-free 的闭环反馈(见证探针)在未见库上被堵死——**模型连库都不会用,写不出能跑的见证程序**。
5. **shared-receiver 是静态硬天花板**(3 库文档未描述)。
6. **LLM 读文档提规则召回更高**(救活了 Φ 漏掉的 simpleconf SR、simplug RF),但噪声大;而其噪声**无法用执行认证清除**(同第 4 点)。

## 6. 局限与下一步

**局限**
- 公平实验仅 **1 个 7B 模型、2 个库(16 任务)、K=3**,单轮方差大(B5_loop 曾 0.688↔0.500 跳动);需 ≥5 轮 + bootstrap CI。
- dev/held 多为 1+1 输入,且两输入常近似 → held-out 泛化测试偏弱;应做输入扩增。
- κ 归因准确率尚未单独量化。

**下一步(优先级)**
1. **命门消融**:`B1+通用prompt反馈(self-debug,无 typed 规则)` vs `B5_loop(Φ)` —— 确认 typed 归因是否超出普通自修复(决定方法**有没有创新**)。
2. **多轮 + CI**:把公平闭环 0.688 这个数坐实。
3. **接 1 个前沿模型**:唯一可能松动"正确性/见证程序"这堵墙的变量(也是 P7)。
4. **写作定位**:B4(gold)作为 skyline 上界,主张锚在"公平 typed 闭环 ≫ B0–B3"+"正确性瓶颈刻画"+"SR 静态天花板",**不主张超过 B4**。

---

> 一句话:**这一轮把 B5 的"接近 B4"祛魅了——那是泄漏的产物;公平之后,B5_loop 能稳赢 B0–B3 但够不到 B4,因为真瓶颈是 test-free 地产出"正确"成对规则,而这件事(尤其 shared-receiver)有静态与模型能力的双重天花板。**
