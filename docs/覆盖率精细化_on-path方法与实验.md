# Execution coverage 精细化（on-path crash 专属）—— 方法与实验

> 2026-07-04。范围锁定：**只做 on-path crash**（金标行必被失败测试执行）。off-path 出局。
> 因为 off-path 不管，on-path 上**硬过滤到执行集是安全的**（金标必在执行集内，不存在 −45 灾难），
> 且本身已强（RQ3-E1 离线 +14pp）。所以真正要证明的不是"要不要过滤"，而是：
> **过滤到执行集之后，覆盖率能否把金标在执行集内部排得更靠前（抬 R@1/R@5），并且能否通过条件化生成把盲投漏掉的金标捞回来。**
> 代码：`region_loc.py`（门控、默认字节不变）+ `rq3/cov_refine_eval.py`（实验）。

---

## 1. 四条通道在 on-path 上各自怎么优化（②frontier 已砍，off-path 专用）

| 通道 | 机制 | 落点 | 为什么过滤器做不到 |
|---|---|---|---|
| **① 输入端** | 投票 prompt 标注执行行（`>`）+ 前置 crash traceback + "沿执行路径反推根因"指令 | `region_loc._vote(cov_annot=, crash_ctx=)` + `COV_REGION_RANK_PROMPT` | 过滤只删输出，改变不了 LLM **生成什么**；条件化生成能捞回盲投漏掉的金标（抬池召回上限） |
| **③ 输出端（升级）** | 把二值执行/未执行、扁平 `+0.8` 覆盖分，换成**分档 RRF 臂**：crash 帧内(tier3) > 执行(tier2) > 未执行(tier1，保留不删) | `region_loc._rank_cov` | 二值过滤对执行集内部 259 行不做区分；分档臂在执行集内部再排一层 |
| **④ 判别端** | 执行集 top-N 缩池后**再做一轮自洽投票**（生成式，非裁判），第二轮票**融合**回第一轮存活集重排——**不替换头部**（n=8 时"头+尾"式替换把存活金标挤出 top-10，改融合后 A4 集合 = A3 集合，R@10 只升不降）| `cov_refine_eval` A4：`_vote` on 缩小 pool + 融合 | 过滤不做第二轮判别；缩池重投是把已证实的投票发动机搬到更小草堆 |
| **⑤ 控制端** | on-path 下路由退化，收缩为**置信/tie-break**：执行且跨样本一致 = 最强单注 → 分档臂 within-tier 先按 counts 再按 freq | `_rank_cov` 的 `xr` 键 | 过滤给不出"执行∧一致"的联合置信 |

**核心方法学**：off-path 不管 → 硬过滤安全 → 五臂**共享"过滤到执行集"这一步**（A2/A3/A4 的存活集合 = A1，R@∞ 相同），差异全在**执行集内部的排序 + 生成质量**。这把"覆盖率帮判别"落到了实处：不是当判别证据（已证伪），而是①缩小判别问题规模、③④标注排序先验、⑤提供正交置信。

## 2. 实验设计（`rq3/cov_refine_eval.py`）

**口径**：crash·on-path 子集（n=57，全部单金标文件 + 有覆盖率）、**file-given**（喂金标文件，旁路 file-loc 噪声）、**ARISE-gold**（`clean_gold` 扔空行/注释/纯标点）。图分臂 `line_scores_v2(use_coverage=False)` 在所有臂**恒定**，覆盖率只经显式通道进入 → 干净隔离。

**五臂消融梯**（每上一层加一条通道）：

| 臂 | = | 隔离的通道 |
|---|---|---|
| **A0 base** | 盲投票 + 现役 V0 排序，无覆盖率 | 基线 |
| **A1 filter** | A0 排序后硬过滤到执行集 | RQ3-E1 的 +14pp 动作（**要超过的对象**）|
| **A2 graded** | 过滤 + 分档覆盖臂重排存活集 | ③⑤（执行集内部排序）|
| **A3 annot** | ①标注+crash-ctx 投票 → 过滤 + 分档 | ①（条件化生成）|
| **A4 revote** | A3 + ④执行集缩池重投 | ④（第二轮判别）|

**统计**：Line R@{1,5,10} + MRR；配对 bootstrap 95% CI of Δ(Ai−A0) 和 Δ(Ai−A1)；McNemar 精确检验（discordant 对）。主判据：**A2/A3/A4 vs A1** 是否把金标排得更前（证明精细化 > 朴素过滤）；**A1/A4 vs A0** 复验覆盖率在完整 LLM pipeline 上有效（= 此前 pending GPU 的 RQ3-E4）。n=57 接近绿灯线 n≥60，报 CI 不塌 R@1。

**模型**：DeepSeek-V3（SiliconFlow.cn，`deepseek-ai/DeepSeek-V3`）。可续跑投票缓存 `cov_refine_cache.json`。

## 3. 结果（DeepSeek-V3，n=57 crash·on-path，file-given，ARISE-gold，k=5，735 vote-calls）

**57/57 金标行确认被执行**（on-path 口径成立）。`rq3/cov_refine_result.json`。

| 臂 | 通道 | Line R@1 | R@5 | R@10 | MRR |
|---|---|---|---|---|---|
| A0 base | 无覆盖率 | 35.1 | 56.1 | 71.9 | 0.451 |
| A1 filter | 朴素硬过滤 | 35.1 | 59.6 | 70.2 | 0.461 |
| A2 graded | ③⑤ | 38.6 | 59.6 | 70.2 | 0.491 |
| **A3 annot** ⭐ | **①③⑤** | **38.6** | **64.9** | **75.4** | **0.507** |
| A4 revote | ①③④⑤ | 35.1 | 63.2 | 73.7 | 0.493 |

**三条核心结论（全部诚实）**：

1. **朴素硬过滤在强 LLM ranker 上基本是 wash**：A1 vs A0 = R@5 +3.5 / **R@10 −1.7** / MRR +0.010。离线 +14pp（弱静态 ranker）**不迁移**到 LLM ranker——LLM 本就隐式把执行行排高，硬过滤删的多是已死的干扰行，偶尔还把 top-10 的金标挤掉。**这坐实了"单纯当 filter 太粗糙"**。

2. **优化后的 A3（①条件化生成 + ③⑤分档 crash-frame 重排）是最优臂，两个基线全面碾压**：
   - vs A0（无覆盖率）：R@1 +3.5 / **R@5 +8.8** / R@10 +3.5 / MRR +0.056
   - vs A1（朴素过滤）：R@1 +3.5 / R@5 +5.3 / R@10 +5.3 / MRR +0.046
   - **MRR 单调递增** A0(.451)<A1(.461)<A2(.491)<A3(.507)：每加一条通道金标就排得更前，剂量-反应干净。
   - 通道分解：③⑤（A2 vs A1）抬 R@1 +3.5、MRR +0.030（执行集内部按 crash-frame 邻近+一致性重排）；**①（A3 vs A2）抬 R@5/R@10 各 +5.3**（条件化生成才能抬池召回，与理论预测一致——过滤只动排序、生成才动召回）。

3. **通道④（缩池重投）不划算**：A4 vs A3 全面小幅回退（R@1 −3.5 / R@5 −1.7 / R@10 −1.7）。on-path 上第二轮投票无增益、略伤。**去掉**。

**统计功效（诚实）**：n=57 下多数 per-k 二值命中 Δ 的 bootstrap CI 未排除 0（A3 vs A0：R@5 +8.8 CI[0.0,17.5] McNemar 6↑/1↓ p=0.125；MRR +0.056 CI[−0.009,0.127]）——**方向一致且强、MRR 明确上升，但 n=57 对二值命中率欠功效**。要 CI 干净排 0 需扩到全 300 或更大 crash 池。机理侧证：20 个"可判别修复"实例（A1 漏 top-1 但金标在 top-10）里 A3 把 4 个提到 top-1；R@5 相对 A0 6 增 1 减。

**一句话**：coverage 帮行定位不是靠过滤输出，而是靠**①条件化 LLM 生成（喂执行路径+crash 上下文）+③⑤按 crash-frame 邻近和跨样本一致性分档重排**——A3 比无覆盖率 R@5 +8.8、比朴素过滤 R@5 +5.3，MRR 随通道叠加单调上升。这就是"execution coverage 帮到判别"的落地证据。

## 4. ⚠️ A0/A3 绝对值口径审计（2026-07-04，数据反证 + 5-agent 对抗式代码审计 `wf_5d4d5f9e`）

**A0=35.1/56.1/71.9 无代码泄漏，但绝对值与端到端 SWE-bench(~15%)、我们自己旧的 27% 不可直接比。** 结论经数据反证 + 独立读码审计双重坐实：

- **无泄漏（4 攻击向量全过）**：patch/test_patch 从不进 prompt；`gold` 只出现在 skip-gate、meta、hit()/rr() 打分三处，从不进 ranker；region/score 只用 issue+AST+图（A0 显式 `coverage_lines=None, failure=""`）。**决定性证据**：A0 R@10 命中 41 < 金标在区域内 53 → hit() 是真 top-k 排序命中，不是区域成员命中（否则两数相等）。
- **null 反证**：同 57 题同 file-given，随机排序 R@10=12.2、纯静态图=29.8、A0-LLM=71.9 → LLM 真在定位，非指标假象。金标中位 3 行（占文件 0.4%），any-hit 口径没占便宜。
- **虚高来自协议（按影响排序）**：① **file-given 最大**——给金标文件旁路了文件定位（仓库自测 file R@1=63.3，端到端 line R@1 只有 29.0，~37% 实例文件就错）；② **单文件限制**（`len(gold_files)!=1` 跳过，难的多文件 bug 被排除）；③ crash·on-path 易子集（区域天花板 93%、投票池召回 87.7%）；④ ARISE-gold 清洗抬天花板 0.78→0.90；⑤ any-hit R@k + 小金标。
- **子集选择 caveat（minor，须披露）**：crash·on-path 用 `gold∩coverage` 选出（含测试期不可得的 gold 信息），但**不虚高 A0**——on-path 对 gold-blind ranker 反而更难（静态代理 on-path 29.8 < off-path 55.6），是正交/反相关，非 cherry-pick。作为 scope 假设披露。
- **内部配对 delta 仍有效但欠功效**：协议虚高是共同偏移，在同实例配对差里抵消 → A3−A0/A3−A1 的 +3.5~8.8 方向可信；但 n=57 下 McNemar p≥0.125、多数 bootstrap CI 触/跨 0 → **只报效应量+CI，标注 underpowered，不得声称"显著"**。

**A3 仍低的精确分解**（pool recall 89.5%）：got@1 38.6% · 在 top-10 不在 #1 **36.8%（判别墙，最大）** · 在池不在 top-10 14.0% · 从没投出 10.5%（生成天花板，不可救）。严格 fraction-recall（全部金标行进 top-10）仅 48.5%（中位 50%，17/57 全中）——报告的 any-hit R@10=75.4 偏宽松。

**待补以直接回应质疑**：① 加报**端到端**口径（不给金标文件，跑文件定位）让绝对数可比；② 主表并列**严格 fraction-recall**；③ 扩样固化 CI。

## 5. 诚实边界 / 待补

- **file-given 口径**：隔离覆盖率对行排序的作用，不含 file-loc。端到端另说（Task 1 的 Agentless/CoSIL 宿主）。
- **失败测试来源**：覆盖率取自缓存（整测试文件执行）。端到端时 FAIL_TO_PASS 可能是 patch 新增测试（oracle 嫌疑）——见 `docs/可复现基线与覆盖率细化方案.md` §1.4。file-given 内部消融不受此影响（配对同口径）。
- **通道①风险**：条件化生成最接近已证伪的"覆盖率喂 prompt 当裁判证据"，区别是喂生成而非逐候选裁判——A3 vs A2 的配对 CI 是它是否踩同一盲区的判据。
- pass 覆盖仅 4 例 → SBFL 的 ep 项（fail-only 分档）本轮未开，分档臂用 crash-frame 邻近替代。
