## 0. ARISE 现状（实查结论，论文可直接引用的说法）

- **论文真实存在**：arXiv 2605.03117，"ARISE: A Repository-level Graph Representation and Toolset for Agentic Fault Localization and Program Repair"，Seddik & Fard（UBC），2026-05-04。方法 = SWE-agent 式 agent loop + 多粒度程序图（文件/函数/语句节点 + 过程内 def-use 边）三层工具 API；排序分 = TF-IDF issue 相关性 + 图跳数邻近 + 数据流切片成员指示（Eq.1）。Backbone 确认 = Qwen2.5-Coder-32B（与我们锁定一致）。
- **41/62/74 协议确认**：端到端（不给金标文件）、全 300 题、Line Recall@k = top-k 内 ≥1 金标行的实例占比。Table 4 全景：RAG 5/12/18 · SWE-agent 26/43/53 · ARISE-Structural 31/48/59 · ARISE-Coarse 32/49/60 · ARISE-Slicing 38/59/71 · **ARISE-Full 41/62/74**；file/function R@1 = 67/60。
- **闭源坐实**：全文无任何代码/artifact 链接或承诺；一作 GitHub 无相关仓库；GitHub 搜 arXiv ID 零结果；无 OpenReview 记录；唯一引用它的论文（DUALVIEW, 2607.01929）只在 related work 提及、无行级数字。**安全措辞**："no public implementation, no artifact statement, and no independent reproduction exists to date"。
- ⚠️ **两个坑**：① 我们的 `arise_static` 与论文任何 arm 都不对应（最接近 ARISE-Structural 31/48/59）——继续用"ARISE 风格静态切片基线"的诚实标注；② 论文金标定义（§3.5）只排除 context 行和**空行**，**没有明确排除注释行** → 我们 `--arise-gold` 比它更严格，同表对比需加脚注。

## 1. Task 1 结论：主基线 = Agentless，第二基线 = CoSIL

### 1.1 为什么是 Agentless（github.com/OpenAutoCoder/Agentless，FSE 2025，MIT，2.1k★）

唯一同时满足全部硬条件的候选：

| 硬条件 | 核验结果（逐文件实查） |
|---|---|
| 原生行级输出 | `localize.py --fine_grain_line_level`：prompt 要求输出 `line: N`（FL.py `obtain_relevant_code_combine_top_n_prompt`）；`--num_samples 4 --temperature 0.8` 多采样 |
| 换我们的底座 | `api_requests.py` 走 openai client → `OPENAI_BASE_URL=http://localhost:8000/v1` 直连 vLLM；多采样用 OpenAI `n` 参数（vLLM 支持）。CoSIL 论文已用 Qwen2.5-Coder-32B 跑过 Agentless 定位（外部锚点） |
| 社区公信力 | OpenAI/DeepSeek 官方拿它当 SWE-bench 脚手架；CoSIL/LocAgent/OrcaLoca/RepoGraph 都复跑过它 |
| 免费自检 | v1.5.0 release 附完整 GPT-4o Lite 定位输出（`agentless_swebench_lite.zip`, 724MB）→ **不开卡就能先在我们 harness 上打分，验证 eval glue** |

**已知锚点数字**（引用时注明第三方复测）：CoSIL 论文用 Qwen2.5-Coder-32B 复测 Agentless（Lite）：file Top-1/3/5 = 58.3/73.0/73.3、function 24.7/39.7/42.7（和我们自己跑的 Agentless AWQ file 58.6/73.7/81.8 量级吻合）。**行级 R@k 从没人发表过 → 我们是第一个测的**，投票协议要写死并对所有臂一视同仁。

**需要的小补丁**（共 ~4 天工作量）：
1. `--model` 的 argparse choices 硬编码 → 删 1 行，或 vLLM `--served-model-name gpt-4o-2024-05-13` 零代码绕过；
2. embedding 检索分支（`Index.py` 的 `text-embedding-3-small`）是唯一 OpenAI 硬依赖 → 用 prompting-only 文件定位（论文 Table 2：contains-GT 78.67 vs 81.33，代价 2.7pp，写进 deviation 说明）或指到本地 embedding 服务；
3. 投票转换器（自写 ~50-100 LoC）：`found_edit_locs` 是每采样一个**无序集合**（`line:` + `function:`/`class:` 混合）→ 跨采样频次投票 + `transfer_arb_locs_to_locs()` 展开函数/类条目 → ranked line list。`--num_samples` 提到 16-32 让排序平滑。

### 1.2 第二基线 CoSIL（github.com/ZhonghaoJiang/CoSIL，ASE 2025）

- **backbone 正好是 Qwen2.5-Coder-32B**（headline 数字，无换模型争议）；repo 附论文原始输出，核验 agent 本地跑 `evaluation/FLEvalNew.py` **复现到小数点**（function Top-1/3/5 = 43.33/54.67/58.00；file 61.33/78.00/83.67）——复现性证据全场最强。
- 行级已在 repo 接线：`CoSIL_localize_line.py` 直接用 Agentless 的 edit-location prompt 吃它的函数级输出 → 和 Agentless 共用同一个投票转换器，边际成本 ~1 天。
- 风险：无 LICENSE（跑对比没问题，重分发要联系作者）、23★ 低社区验证（我们的复跑本身就是验证）、`localize_line` 的 token 上限断言要加保护。

### 1.3 其他候选为什么不行（一句话版）

LocAgent（ACL'25）：函数级 + 32B-CL 微调权重有严重 repro 问题（issue #22 vLLM 空输出未回应；stock Qwen 上塌到 ~10）；SweRank（ICLR'26）：函数级 + 微调检索范式破坏同底座故事 + 274 子集协议不同；**BugCerberus**：除 ARISE 外唯一发表 Lite statement 级 Top-k 的，但**闭源**（只放数据集）+ 3 个微调模型——只引用作口径校准（它复测的 Agentless statement Top-1/5/10 = 23.0/36.4/36.8 可当外部 sanity 区间）；OrcaLoca/KGCompass/SWE-Fixer/Moatless：函数/文件级或 backbone 不符，cite-only。

### 1.4 实验设计与预期（诚实算术）

**表设计**（全部同一投票转换器、同一 `--arise-gold` 口径、配对 bootstrap + McNemar）：

| 臂 | 说明 |
|---|---|
| Agentless-FL (Qwen-32B) | 行级 R@{1,5,10}，全 300 + crash/behavioral × on/off-path 分层 |
| Agentless-FL + gated-cov | 我们的 filter（§2 路由版）挂在其行级候选上 |
| CoSIL (Qwen-32B) 同两行 | 第二宿主 |
| ours_static / ours+cov | 自己的方法作第三宿主 |

**预期增益（拿 RQ3-E1 外推，别超卖）**：on-path 硬过滤增益 = crash +14.1、behavioral +6.9（R@10）→ 若 router 完美且 off-path 零损失，全集期望 ≈ (57×14.1 + 131×6.9)/300 ≈ **+5.7pp R@10**；router 打折后现实预期 **+3~5pp**。分层表里 crash on-path 是 +10pp 量级的显眼增益。**卖点框架 = "对任意静态 localizer 即插即用、增益一致"（三宿主）**，这比单点超过某 SOTA 更硬。

**两个致命混淆（完备性裁判，必须先处理）**：
1. **金标文件泄漏**：离线 +14pp 是在金标文件覆盖上算的。挂到 Agentless 时 filter 必须作用于 **Agentless 自己定位出的文件**的覆盖（`cov_collect` 本来返回全 repo dict，数据不缺）；代码里严禁用金标文件身份选覆盖。
2. **失败测试来源**：FAIL_TO_PASS 测试常是金标 patch 新增的 → oracle 嫌疑。三选一：(a) 审计 n=57 里 pre-patch 已存在的测试占比、只用这部分；(b) 用 Agentless 自己的 reproduction-test 生成阶段产出的测试收覆盖（完全端到端，最干净）；(c) 显式声明假设 + 引 AutoCodeRover-SBFL（同样假设）+ LIBRO（issue→test 可合成）。建议 (a) 审计 + (b) 做主口径。

**开工前 must-verify**（半天）：① vLLM `n>1` 采样过 `OPENAI_BASE_URL` 冒烟（5 题）；② 用 released GPT-4o artifact 免费打分验证投票转换器；③ pre-patch 测试审计脚本。

## 2. Task 2：覆盖率细粒度化 —— 从"二值 filter"到"分档先验 + 边界打分 + 缩池重投"

### 2.0 设计约束（来自我们已证伪的死路，不可违反）

- ❌ coverage 当 LLM 打分项/裁判证据：已证伪（+0.8 打分惰性 300 改 1；judge/test-ev/multi-view 全删，同模型弱验证器 CI 全含 0）。
- ❌ 二值硬过滤全局套用：off-path −45.5 归零。
- ❌ 重排冻结候选集救召回。
- ✅ 唯一被证实的发动机 = 区域收窄 + 自洽投票 + RRF；final-pick（缩池精选）是唯一有方向性正增益的 LLM 杠杆（+5.6 R@1）。
- 数据形态：现有缓存只有**执行行号集合**（fail 全量 258 例 + pass 4 例）+ issue traceback。无 hit count/branch arcs/执行顺序（重采集贵，设计按此分层）。

**核心思想**：覆盖率不喂给 LLM 判断，而是①**程序化地改变排序先验**（分档，代替二值），②**程序化地改变 LLM 看到的草堆大小**（缩池重投——用被证实的生成引擎，不用被证伪的验证引擎）。这正好回答"execution coverage 能否帮判别"：**能，但帮法是缩小判别问题的规模和标注先验，而不是当判别证据**。

### 2.1 组件 P：三档软先验（替代二值 filter）

文献模板：GenProg weighted-path（1.0/0.1/0 软权重）、Renieris 最近邻差分覆盖、单失败测试下 SBFL 各公式退化为"未执行=地板分、已执行按 ep 降序"（Naish/Xie 等价类理论）。

| 档 | 定义 | 数据 |
|---|---|---|
| A（最高） | fail 执行 ∧ pass 未执行（无 pass 覆盖时退化：fail 执行 ∧ 位于 traceback 帧函数内） | fail 缓存 + pass 缓存/traceback |
| B | fail 执行 ∧ pass 也执行（共享 setup/import 噪声，降权不删） | 同上 |
| C | 未执行但在覆盖边界上（§2.2 frontier） | fail 缓存 + AST |
| D（ε>0） | 其余未执行 —— **不归零**（LEVER 教训：硬过滤扔掉 correct-but-atypical；这是超越硬过滤 43.9 天花板的关键） | — |

进入现有 RRF 作为一个 ranker arm（票数 + def-use 分 + 覆盖档位序）。RRF 需要有梯度的排序，分档正是把"近二值的覆盖"变成合法 ranking 的手段。pass 覆盖扩采集走已有 `rq3/cov_collect_pass.py` Docker 管线（不占卡）。

### 2.2 组件 F：覆盖边界（frontier）打分 —— off-path 从"路由掉"变"利用" ⭐ 新颖性主张所在

off-path 机制已分类（`rq3/classify_offpath.py`：漏分支 6 / 插入 4 / 函数未达 1）。这些金标行不在覆盖集，但**紧贴执行边界**，全部可用现有行集合 + AST 离线算：

1. **partial-branch**：`if`/`for` 行被执行而其 body 未执行 → 该边界行提档，且按衰减把分传播给未执行块前 k 行（Santelices ICSE'09 branch-spectrum score mapping 的行级版）；
2. **插入锚点**：紧邻执行行的未执行/空隙位置 → 承接执行邻居的分（Nopol angelic localization + Pearson ICSE'17 的 omission-fault 邻接评分惯例——领域自己的评测惯例，护甲很硬）;
3. **未调用函数**：call site 被执行而函数体未执行 → call-site 分传播给函数体首行。

可选升级（贵，future work 或小子集）：predicate switching / guard-only mutation 用 Docker 重执行动态认证边界行（FauxPy 有 pytest 实现）。

### 2.3 组件 V：coverage 条件化缩池重投（你的构想，修正为"证据保留式"）

```
Stage-1: 现状（区域收窄 + SC 投票 k + RRF）           ← 不动
Narrow : 候选池 ∩ (档A∪B∪C)，池从 ~200 行缩到 ~30-60 行  ← 程序化，0 LLM
Stage-2: 对 narrowed pool 再做自洽投票（生成式，不是裁判）
输出   : Stage-2 重排头部 + Stage-1 序接尾部（set 不变，R@∞ 不降 = 召回地板）
```

- 与已死的 judge 的本质区别：judge 是**验证**（"这行要改吗？"，同模型盲区），这里是把被证实的**生成**引擎放到更小草堆上再跑一次。文献支撑：RankGPT（LLM 判别力受列表长度硬约束）、TourRank（shrink+re-vote 调度）、CodeMonkeys（filter→select 优于任一单独）、AlphaCode（execution-narrow 后共识投票）。
- 内部证据：final-pick（top-N 缩池精选）是全项目唯一方向性正增益的 LLM 杠杆——组件 V 是它的推广（缩池方式换成 coverage 条件化、输出换成重排）。
- 成本：每题多一轮小 prompt 投票（池小，token ≈ Stage-1 的一半）。

### 2.4 组件 R：on/off-path 路由器（CraTer 模板：fault residence >92% 可预测）

无金标时的 gate 特征（全部离线可算）：issue 是否含 traceback、traceback 帧文件是否被覆盖、候选行覆盖比例、issue 提及符号是否在覆盖集、crash/behavioral regex 分类。
决策：**on-path → P+V 全开；疑似 off-path → 只开 F、不 narrow**。评测先报 oracle-routing 上限，再报 predicted-routing 现实值（router 质量本身成为一个结果）。

### 2.5 实验路线（先离线榨干，再开卡）

| RQ | 内容 | 算力 | 判据 |
|---|---|---|---|
| RQ-A | P（三档先验）vs 二值 filter vs 无覆盖，def-use ranker，4 子集 | **0 GPU** | on-path 不低于 +14.1；off-path 从 −45.5 回正 |

### 2.6 新颖性定位（调研结论：没人做过，但四邻都有人，claim 要窄）

- **必引必区分**：AutoFL/AgentFL/LLM4FL（coverage 缩 LLM 搜索空间，但 method 级、Defects4J；LLM4FL"覆盖排序本身 +22% Top-1"可引证软先验优于硬过滤）；AutoCodeRover-SBFL（SWE-bench 上唯一 SBFL 先例，method 级 hint、+3.33pp resolve——同时用它защит failing-test 假设）；FuseFL（line 级 SBFL 进 prompt，但单文件学生作业）；**SemLoc 2026**（line 级 execution-fused，但专攻 coverage 失效 regime——恰是我们 off-path 的镜像，引它坐实 on/off-path 二分是公认现象）；TestPrune（SWE-bench 上 line coverage 但反方向：定位选测试）；LLMAO（line 级但无执行信号）。
- **可 claim 的确切 gap**：单失败测试 per-line 覆盖 → 可靠性路由的分档先验 + 覆盖边界打分（rank unexecuted lines，SBFL 结构性做不到）+ coverage 条件化缩池重投，在 repo 规模 issue localization 上以 Line R@k + on/off-path 机制刻画评测。
- **"这就是 SBFL+LLM"的预答**：regime shift（单失败测试、无通过谱统计、repo 规模、issue 驱动）+ 测得的 off-path 灾难与 gate + frontier。
- **并发风险**：SWE-Doctor（2026-07）已做"failure 必须到达定位代码"的 screening（函数级）；ADI 明说因成本放弃行级动态信息。**行级窗口还开着，但要快发。**
