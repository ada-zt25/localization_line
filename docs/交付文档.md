### C1 实证：行级定位是前沿真瓶颈
| 文件 | 实验 | 交付结果（结果 json）|
|---|---|---|
| `p0_line_recall.py` | **P0** 单文件、文件已给、选行（含跨规模）| 精确行 recall：qwen **0.165** / gemma **0.307** / DeepSeek‑V3 **0.584**；函数级 0.78 → **粒度 gap**。`p0_ollama_qwen_diverse.json` / `p0_ollama_gemma2_9b.json` / `p0_openai_deepseek_v3.json` |
| `analyze_by_size.py` | **P0‑big** 按文件规模分层分析 | 大文件 precision 0.49→**0.20**、过预测 1.9×→**5.8×**（精确性墙）。`p0_dsv3_bigfiles.json` |
| `p1_realistic.py` | **P1** 真实两阶段（不给文件）| 文件级命中@5 **0.90**；e2e 行 recall **0.53**；23% 完全 miss。`p1_openai_deepseek_v3.json` |
| `p2_multifile.py` | **P2** 多文件（最真实）| 文件级 recall@10 0.66；找全文件仅 **0.35**；global 行 recall **0.28**。`p2_openai_deepseek_v3.json` |

→ 行级 recall 随真实度单调恶化 **0.53 → 0.28 → 0.15**（0.15 为独立基准 SWE‑Explore）。

### C2 排错+机制：纯执行覆盖做不了行级定位
| 文件 | 实验 | 交付结果 |
|---|---|---|
| `egl_makeorbreak.py` + `egl_analyze.py` | **EGL** Docker 内跑失败测试取覆盖 vs 静态 LLM | 精确执行行 **0.33** / 被执行函数 **0.96 但占 85% 文件** / 静态 LLM **0.42** → **覆盖证伪**。`egl_coverage_clean2.json` |
| `p3_repro_signal.py` | **P3** 复现测试“文本”注入 | Δ **+0.00**（文本无效）。`p3_openai_deepseek_v3.json` |
| `p4_risk_a.py` | **P4** 复现可合成性量化 | **93% 可合成**复现测试 → “无信号”非结构性墙。`p4_risk_a.json` |

→ 机制 = **bug 类型门控**：崩溃类 traceback 可点名；行为/断言类返回错值、栈已弹出、覆盖被 import 淹没，执行对行级“不透明”。

### C3 新方法：静动结合的执行‑反馈‑修复闭环（hybrid_loop，原代号 P8）
方法本体 = 静态提 SEARCH/REPLACE 编辑 → Docker 跑测试 → 报错反馈 → 再定位，K=5，并集为定位。
现以 **ARISE 风格代码图**（`code_graph.py`）增强**两环**，并扩到**仓库级 agentic 设定**：

| 文件 | 作用 | 交付结果 |
|---|---|---|
| `hybrid_loop.py` | **hybrid_loop** 方法本体 + **4 变体消融**（A0 static_plain / A1 static_graph / B0 loop_plain / B1 loop_graph），单文件文件已给（与原 P8 同口径）| 原 loop_plain：fraction‑recall **0.393 → 0.557（+42%）**；xarray‑4075 0→1.0。图增强（A1/B1）结果见 `hybrid_loop.json`（扩规模运行中）。 |
| `code_graph.py` | **ARISE 式多粒度程序图**（纯 `ast`）：Module/Class/Function/**Statement** 节点 + Contains/Imports/Calls/Inherits + **语句级 def‑use 数据流边**；提供 `skeleton`/`dataflow_slice`/`rank_suspect_lines`（=ARISE build_context_bundle 打分，给出 P8 缺的置信排序）/`rank_files` | 被两个实验 import。借鉴 ARISE（arXiv:2605.03117）。 |
| `hybrid_loop_agentic.py` | **实验二**：仓库级、文件不给的真实 agentic 设定。S1 文件定位（静态 ⊕ called‑coverage ⊕ 图重排）→ S2 图增强行定位 → S3 多文件执行‑反馈闭环（traceback 重新播种候选）| 文件级/行级 recall@k 见 `hybrid_loop_agentic.json`（扩规模运行中）。 |
| `hybrid_loop_watchdog.py` | 运行看门狗（hl_/hla_ 容器）：自动清理卡死容器 + 周期回报 | — |
| `hybrid_loop_analyze.py` | 4 变体消融分析：图静态增益（A1−A0）、闭环 recall 增益、图排序增益（B1−B0）| — |
| `eval_recall_at_k.py` | **ARISE 同口径** Line Recall@1/@5/@10，读 4 变体并出消融表 | 原 P8：静态 66.7/83.3/100 vs loop_plain 8.3/66.7/91.7（无置信排序而吃亏）；loop_graph 用图排序补这一缺口（见 `hybrid_loop.json`）。 |
