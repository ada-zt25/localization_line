- **必打的 torch 补丁（克隆实例会丢，每次重开都要打）**：vLLM 0.23 要 `torch._inductor.kernel.mm_common` 里的 `mm_configs`，但这台 torch 没有 → 报 `ImportError: cannot import name 'mm_configs'`。这是**顶层 import**，`--enforce-eager`/环境变量都挡不住，必须改文件：
```bash

bak = f.with_suffix(".py.bak"); src = f.read_text()
if not bak.exists(): bak.write_text(src)
patched = re.sub(r"^from \.mm_common import .*$",
    ("from . import mm_common as _mmc\n"
     "mm_args = getattr(_mmc, 'mm_args', None)\n"
     "mm_grid = getattr(_mmc, 'mm_grid', None)\n"
     "mm_configs = getattr(_mmc, 'mm_configs', lambda *a, **k: [])\n"
     "mm_options = getattr(_mmc, 'mm_options', lambda *a, **k: {})"),
    src, count=1, flags=re.M)
f.write_text(patched); print("PATCHED OK")
PY
```

## 1. 实验设定 / 数据集处理

- **任务**：行级 fault localization，file-NOT-given（先找文件再定位行），口径对齐 ARISE。
- **数据集**：SWE-bench Lite，**全部 300 实例**（`--broad --sample 300`）。`egl_e2e.select_pool_mixed` 选取：PY-repo、gold 编辑全为 .py、有 FAIL_TO_PASS，`Random(0)` 打乱。**评测集始终 300，没有缩水。**
- **口径统一**：两条对比臂（ARISE 静态行定位 vs 我们动态行定位）用**同一套 ARISE 文件定位**；第二阶段用 `--reuse-files` 复用第一阶段的文件定位结果，保证差异**只在行定位**。
- **模型**：bf16（比之前 AWQ 强，也更贴近 ARISE 的全精度设定，对齐更好）。
- **覆盖率是「输入信号」不是评测集**：某实例有没有覆盖率不改变它是否被评测，只影响其动态臂能否拿到执行信号。最终 `n_with_coverage = 250/300`。

## 2. 今天做了什么（方法改造 + 实验）

### 2.1 方法/代码改造
1. **复刻 ARISE agent 文件定位**（新文件 `arise_file_loc.py`）：仓库级程序图(`RepoIndex`，从 tarball 快照建：Contains/Imports 边 + 相对导入解析 + 实体名索引) + 分层工具(search_code/search_entity/get_skeleton/get_imports/get_importers/read_lines) + ReAct agent 循环。修了三个 bug：①循环重复读同一行 → 加重复调用检测；②把测试文件排到第 1 → 降权测试文件；③不给答案 → 强制收尾。`egl_e2e --file-loc arise|agentless`。
2. **激活覆盖率(动态半边)**：`egl_e2e --coverage` 先 Docker 收集失败测试执行行 → 写 `egl_cov_cache.json` → 把 `coverage_lines` 喂进 `region_line_loc_ex`，点亮 `code_graph` 的 `δ·covered`、`rank_functions +1.5`、模块行覆盖加分。
3. **仓库感知的覆盖率收集器**（新文件 `cov_collect.py`）：从 **test_patch** 推断测试文件 + 按 repo 选测试运行器：**Django 用 `tests/runtests.py --settings=test_sqlite --parallel 1`**，其余用 pytest；都装 coverage+pytest 后跑。只喂真正的 `test_*.py`（丢掉 `tests/roots/` 夹具文件）。
4. **一次跑齐 5 臂分解 + 诊断指标**（`egl_e2e` summarize）：每实例 5 条行定位臂(arise_static / vote_only / ours_static / ours_dynamic_nofp / ours_dynamic)各 R@{1,3,5,10}+recall+prec+F1；配对 bootstrap 增量(覆盖率效应/final-pick效应/vote+graph vs 静态切片)；诊断(reg_ceiling/voted_ceiling/cov_on_gold_recall/found_file_lines 等)。
5. **提速旋钮**：`--cov-workers N`(并行 Docker)、`--prefetch-coverage`(只收覆盖率、与 GPU 运行重叠)、`--reuse-files`(两臂共用一次 agent 文件定位)、`--arise-turns 8`。全部可断点续跑。
6. **清理**：删了 12 个废弃文件(egl_agentic/probe_ablation/p2-p5/旧 DeepSeek 跑批脚本等)，保护覆盖率链路。

### 2.2 主实验（全程 n=300）
- **Phase 1 静态臂**（覆盖率 OFF）：`--file-loc arise --arise-turns 8 --final-pick 8 --rank-mode v0 --out egl_e2e_ARISE_static.json`。
- **覆盖率预收集**（Docker，与 Phase 1 重叠）：`--prefetch-coverage --cov-workers 8`。
- **Phase 2 动态臂**（覆盖率 ON，复用 Phase 1 文件定位）：`--file-loc arise --coverage --reuse-files egl_e2e_ARISE_static.json --final-pick 8 --out egl_e2e_ARISE_dynamic.json`。

## 3. 结果

### 3.1 主对比表（n=300）
| 配置 | line R@1 | R@5 | R@10 | file R@1 |
|---|---|---|---|---|
| **ARISE 参考** | **41** | **62** | **74** | 67 |
| **ours_dynamic（完整方法）** | **27.7** | **43.0** | **47.3** | 63.3 |
| ours_static（vote+graph，无覆盖率） | 24.0 | 41.7 | 47.0 | — |
| vote_only（只投票） | 25.0 | 42.0 | 48.3 | — |
| arise_static（纯静态 def-use 切片） | 8.7 | 22.0 | 26.3 | — |

### 3.2 配对消融（带显著性）
- **覆盖率效应**(ours_dynamic_nofp − ours_static，只差覆盖率)：R@1 **+0.003** / R@5 **0** / R@10 **+0.003**，**全部不显著(p≈0.63)** → 覆盖率没用。
- **final-pick 效应**：R@1 +3.3 / R@5 +1.3 / R@10 0。
- **vote+graph vs 纯静态切片**：R@1 +15.3 / R@5 +19.7 / R@10 +20.7（我们方法真正的价值来源）。

### 3.3 诊断指标
- `reg_ceiling = 0.784`（金标行在选中区域内的比例）
- `voted_ceiling = 0.557`（投票实际捞到金标的比例）→ **区域有金标 78%，投票只捞 56%,中间漏 22 分**
- `cov_on_gold_recall = 0.373`（失败测试只执行了 37% 的金标编辑行）
- `n_found_mean = 0.737`（文件定位找到 gold 文件 74%）；`found_file_lines_median = 813`

## 4. 无法收集覆盖率的测试案例（~47/300，最终 250 有覆盖率）

| repo | 数量 | 原因 | 可修否 |
|---|---|---|---|
| pytest-dev/pytest | 17 | pytest 测自己，用 `pytester` 夹具**派生子进程**跑测试，`coverage` 默认不抓子进程 | ❌ 本质限制（要 COVERAGE_PROCESS_START，脆弱） |
| sphinx-doc/sphinx | 16 | 测试能跑通，但 `coverage --source=/testbed` 抓不到 → "No data"。疑似 sphinx 从**站点包(site-packages)非可编辑安装**运行，路径与 /testbed 不匹配 | 🔶 需 per-repo `--source`/路径归一，**有风险**(可能搞坏已工作的 250)，没修 |
| scikit-learn | 8 | 同上类(部分实例 source 路径/xdist) | 🔶 同上 |
| sympy/django/requests | 3/2/1 | 个别边缘 | 多数已工作 |

**已修好的**：Django(用 runtests.py，原本 pytest 跑不了，已修)、sympy/sphinx 的「镜像里没装 pytest → 加 pytest 安装」、sphinx 的「把夹具文件 `tests/roots/*.py` 误当测试 → 过滤只留 test_*.py」(让测试能跑，但 sphinx 的 source 路径问题仍在)。

**结论**：~250/300 有动态覆盖率，统计上足够测覆盖率效应；剩 ~47(主要 pytest 自测+sphinx)如实标注为收集限制，不影响 ARISE 对比口径(全程 300)。

## 5. 关键结论

1. **没打过 ARISE**：三项 line R@k 全输，主要差在 R@5/R@10(召回)。
2. **覆盖率(Q3 动态半边)无效**：配对效应≈0、不显著。根因：①只执行 37% 的金标行(很多修复是**插入**新行/走未执行分支，覆盖率天然抓不到)；②只当一个弱 +0.8 **排序项**,被投票/图信号淹没,**没用于扩召回**。
3. **瓶颈是召回天花板,不是排序**：Stage-2 投票漏掉 22 分在区域内的金标。`voted_ceiling 0.56` 把 R@10 卡在 ~47，而 ARISE 是 74 → ARISE 的行定位候选召回远高于我们。
4. **文件定位基本追平**(63.3 vs 67),不是瓶颈。

## 6. 下一步工作指导

**主攻方向：抬高 Stage-2 投票召回 `voted_ceiling`(0.56→更高),这是 R@5/R@10 差距的直接来源。** 不要再调排序(R@1 排序空间已不大)。具体可试(按优先级)：
1. **投票别截断/别丢**:`_vote` 看的是排序后截断的区域视图;给全区域、加 `lines_cap`、加 `k_samples`,看 voted_ceiling 是否上升。
2. **换聚合**:RR-vote(reciprocal-rank)可能丢长尾;试「并集召回 + 后排序」或对每个区域块独立投票再合并。
3. **覆盖率重定位为「召回信号」而非排序**:把执行行(及其邻域)**直接并进候选集**(扩 recall),而不是只给 +0.8 加分;或用覆盖率**给区域选择(Stage-1)做种子**。这是让 Q3 真正起作用的唯一可能路径——**但要诚实**:cov_on_gold 只有 0.37,上限有限。
4. **天花板提醒**:端到端 line R@10 ≤ file R@10(=73.7)。想冲 ARISE 的 74,文件定位也得再上去一点。
5. **覆盖率的科研定位(需你决断)**:数据显示它无效。要么(a)按上面 #3 重新设计用法再测一次;要么(b)诚实承认「在本基准上失败」并把论文重心移到 vote+graph 的静态贡献。

### 6.1 反思 workflow 的升级方案（对抗审核版，wf_943a1307）

**R@10 天花板结构（最重要，审核用数据算清）：**
| 层级 | line R@10 上限 |
|---|---|
| 现状 | 47.3 |
| 完美排序当前投票集 | 57.7（纯排序还有 ~10 分） |
| 完美投票(捞全区域内金标) | **67.0（"区域墙"）** |
| 文件墙 = file R@10 | **73.7（gold 文件召回 0.737）** |
| ARISE | 74（**在文件墙之上**） |
→ 光抬投票召回最多 ~67；ARISE 的 74 必须**同时**抬文件召回才够得着。"agentic 扩展逼近 74"被判 FAILS(算术不可能,除非动 file-loc)。

**覆盖率最终裁决：** 现状 300 个里只有 **1 个**实例因覆盖率改变 R@k → 基本惰性。根因(代码已证):`δ·covered` 只是 `list(freq)` 上的排序项,**结构上无法把找到的金标加进候选集**。**可救但只能当 backstop**:32/48 个"投票全漏"实例里覆盖率是唯一命中金标的信号,改成"召回项"(执行过且靠近投票行的行**并进候选集**)→ 召回天花板 0.557→0.676(+12,但 e2e R@10 现实仅 +~1.3,best ~+11)。论文里诚实标注为 backstop、不是 headline。

**⚠️ 方法学坑(审核抓到)：** 提案里 "k=5→20 抬召回到 0.74"、"区域大小梯度 0.78→0.44" 这些量化预测**所依赖的 per-line counts+gold 底料在 repo 里根本不存在**。所以**明天第一步 = `egl_e2e --dump-substrate` 导出 counts+gold,先离线验证再改**。

**升级优先级（对抗审核后）：**
1. **先 dump 底料**(`--dump-substrate`)→ 离线免费验证 k-up/分片真实收益(`ablation_rank_sweep.py` 可复用)。
2. **k-up(5→15~20)**:便宜、召回单调一定有用,但天花板 ~67,具体幅度离线验证(别信 0.74)。`region_loc._vote` 的 `k_samples`。
3. **覆盖率→召回 set-augmentation**:在 `region_line_loc_ex` vote 后,把"在区域内 ∧ 距投票行/高图分行 ±3 行内"的覆盖行并进候选集(给合成低票质,排在尾部保 R@1/R@5)。救 32 个投票全漏实例。**别并入全部覆盖行**(中位 813 行→精度崩)。
4. **要过 67 → agentic 候选扩展 + 抬文件召回**:vote 产出 ~40 行种子后,用 def-use 切片(`code_graph.dataflow_slice` 已存在)做 TOOL、让 LLM 读切片邻居、**扩充候选集**(不是只重排);同时 file-loc 要针对 gold 文件**召回**(0.737)而非只 top-1。这是唯一通往 74 的路,高成本。
5. **重设目标叙事**:从"追平 ARISE 74"改成"先补 47→67 区域墙",明确 0.737 文件墙是再往上的前提。

**审核否决的**:k-up→0.74 的具体数字(底料缺失)、分片的 0.78→0.44 梯度(底料缺失,可用代理只 ~14 分且非单调)、agentic 扩展逼近 74(文件墙)。**审核确认的**:输给 ARISE、投票集冻结只重排、覆盖率惰性(1/300)、覆盖率 salvage 真实(救 32 个)。
