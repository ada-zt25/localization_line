## 6.15 进展：pyparam 弱基准诊断
逐任务核查 + 探测 vendored pyparam 0.5.4 行为后确认：pyparam 的核心 API（`add_param(type=...)` / `parse()->Namespace` / `ns.attr`）语义简单且被 API 清单完全表达，**B1（纯清单）即满分**、B0=0.00（未见但清单一注入就全解）。探测的"非平凡"候选都不适合做干净 oracle：
- `list:int` 会把元素转 int（`[1,2]`），但 **plain `list` 对数值字符串也自动转**（自动类型推断），二者无干净区分；
- `type='py'` 解析不稳（返回 None）；
- 子命令 `add_command` 的参数捕获不可靠（`ns.run.n` 取不到值）。
结论：pyparam 缺少"光看 API 名字会写错"的成对组合约束，强造会牵强脆弱。

**决策已定：从主实验移除 pyparam。** 主实验库变为 **simplug + diot + simpleconf**（2 未见 + 1 熟悉，均有真实组合约束）。已落实：
- `run_full.sh` / `run_quicktest.sh` 默认 LIBS 去掉 pyparam（含注释说明原因）；
- `exec_oracle/audit_injection.py` 默认库列表去掉 pyparam（仍可显式传参审计）；
- `result/pyparam_5model` 归档到 `result/_archive/`（移出 visualize 自动发现范围，保留作证据）；
- `lib_pyparam.py` / `fixture_pyparam.py` 等代码保留（不删，便于将来复用或作为弱基准反例引用）。
- audit 在 3 主库上仍 PASS。
后续若需补回第 4 个库，应找**另一个有真实组合约束的低流行度库**（类 simpleconf/diot），而非修 pyparam。

# 6.17 阶段性总结：接入前沿模型（DeepSeek-V3）做 pivot —— 重大（且诚实的负面）发现

> 本轮目标：下一阶段两个目标是 ①任务扩到 1000+；②让 B5_loop 稳高于 B3 且尽量逼近 B4。三个候选方向（优化 Φ 召回 / 优化闭环 / 接前沿模型）中，**先做"接前沿模型"**——它最便宜、回答审稿 P7、且是其它方向的使能器。结果改变了对整个 B5 方法的判断。

## 一、做了什么（代码）

1. **前沿模型适配层**：`benchlib_generate.call_model()` 按模型名分发——前沿名（`gpt-*`/`o1/o3/o4*`/或显式 `openai:`/`oai:` 前缀，`OPENAI_BASE_URL` 可重定向到任意 OpenAI 兼容端点）走 OpenAI 兼容 API，其余走原 Ollama。**key 只从环境变量 `OPENAI_API_KEY` 读，绝不落盘/入库**。所有模型调用点（`benchlib_generate`/`fair_loop`/`llm_extract`/`rq2_vetted`）统一改走 `call_model`。后加**连接级重试+指数退避**（`RemoteDisconnected`/429/5xx；一次 `RemoteDisconnected` 曾把整条 `fair_loop` 干掉）。
2. **退役泄漏协议（用户决策）**：**删除 `b5_loop_run.py`**（其闭环反馈 oracle == 评测 oracle，等于在测试集上调参；`result/full_run_analysis.md` 的 B5_loop 列即此泄漏口径）。闭环**算法**仍在 `b5_feedback.py`（run_loop/attribute/refine_rule），`fair_loop.py`（dev/held 拆分、等预算 K、held-out 判分）成为**唯一的 B5 来源**；`fair_loop` 加 `--conditions`（默认 `B0,B1,B3,B4,B5_loop`）。`run_benchmark.sh`/`run_full.sh` 去掉 B5_loop 步（只剩 B0–B4 one-shot + 评分）；相关 docs 指针改到 `fair_loop`。
3. **召回修复 `B5_cert`**：新增 `llm_extract.certified_proposals/certified_rules_for_task` = **LLM 读文档提规则 + 执行式见证认证**（LLM 自写 `compliant()`/`violating()`，执行裁定 FIRES/NO_DIVERGENCE/ABSTAIN，保留 FIRES、丢 NO_DIVERGENCE）；`fair_loop` 加 `B5_cert` 与 `B5_llm`（未认证 LLM 规则，做消融）。**修了一个见证 bug**：见证 prompt 原先只给 `HELPER_LINE` → simplug 全 ABSTAIN（模型在未见有状态库上写不出能跑的见证程序）；补上 `API_LIST`+`RAW_API_DOCS` 后 simplug 由 **8 ABSTAIN → 5 FIRES + 2 NO_DIVERGENCE**。
4. **平台**：用 SiliconFlow **国际站 `.com`**（`OPENAI_BASE_URL=https://api.siliconflow.com/v1`，注意 `.cn`/`.com` 是两套独立账号/密钥），模型 `deepseek-ai/DeepSeek-V3`。`.gitignore` 加密钥屏蔽 + 修正失效的 vendor 路径。

`B1=0.81  B3*=0.58  B4=1.00  B5_loop=0.77`。`B5−B3*=+0.19`、**`B5−B4=−0.23`**、**`B5−B1=−0.03`**。
→ 公平口径下 **B5_loop ≈ B1、够不到 B4**。（注：实际可拆任务 **31** 个，跨全部 6 库，比此前文档说的 ~16 多。）

**C. make-or-break：召回修复 B5_cert vs 基线（simplug n=10 + diot n=4）**

| lib | B1 | B4 | B5_loop(Φ) | B5_llm(未认证) | **B5_cert(认证)** |
|---|--:|--:|--:|--:|--:|
| simplug | 0.70 | **1.00** | 0.80 | 0.60 | **0.60** |
| diot | 0.50 | **1.00** | 0.50 | 0.50 | **0.50** |

→ **召回修复在前沿档没成功**：所有 test-free B5（Φ/LLM/LLM+认证）都挤在 B1 附近、够不到 B4；认证版 = 未认证版（去掉 2 条幻觉规则没改变下游）。

## 三、结论（诚实）

1. **成对规则（B4）有效，但有效程度 ∝ 库的未见程度。** 在真未见库（simplug/diot）上,即便对前沿模型,gold 规则也有 **+0.30~+0.50** 的大收益并打到封顶；在模型已熟的库上 ≈0。这是最初 RQ3 论点，且**在前沿模型上依然成立**（"问题不随能力消失，只要库够未见"），是可发表的强结论。
2. **本方法（test-free B5）在前沿模型上无效。** Φ / LLM / LLM+认证三种 test-free 抽取都 ≈ B1，拿不到 B4 的价值。根因即"召回/正确性瓶颈"：强模型不需要帮简单的，难的又需要一条 test-free 产不出的正确规则；前沿模型把这点暴露得更彻底。
3. **论文形态裂成两块**：①【发现，扎实】benchmark + 成对规则在未见库上的价值（B4 skyline，收益 ∝ 未见程度，前沿仍显著）；②【方法 B5，目前是负结果/局限】test-free 自动恢复做不到（前沿档）。

## 四、Caveat 与未决

- **噪声极大**：`runs=1`、温度 0.6、best-of-K=3、每库 n 小（diot 4 / sqlitedict 1–3）；B5_loop 同设置两次跑出 0.50↔0.80。所有具体数字**方向性而非统计坐实**；"B4 永远封顶、无 test-free B5 接近"这一**结构性事实**跨轮稳定。
- **只测了前沿档**：**小模型/边缘 regime（低 B1、有真实 headroom）尚未测**——这正是 `创新思路.md` 的动机（私有库、本地 vibe-coding），也是 B5 唯一可能成立的战场。干净架构：强模型离线提规则+认证 → 注入小模型推理（认证模型/生成模型解耦，需小改 `fair_loop`）。在测之前不下"方法整体无效"的结论。
- **sqlitedict B4<B1（−0.33，n=3）** 异常待查。
- **Goal 1（扩到 1000+）选库标准要升级**：从"7–9B 的 B0 低"改为"**前沿模型 B1 仍低**"（simplug 为范本）；否则新库一上前沿模型就被 B1 解决，B4−B1 论点在前沿档塌掉。

**下一步（待用户定方向）**：①小模型 regime + 解耦认证实验；②多轮（runs≥5）+ bootstrap CI 坐实；③按"发现强、方法作为局限"定稿；④前沿档继续压方法（加大 K / 改进归因精修 / 换 V4-Pro）。
